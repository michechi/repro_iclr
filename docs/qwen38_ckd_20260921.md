# Qwen3.8-27B on CKD → ESRD

This experiment extends the existing MIMIC-IV CKD-to-ESRD case study with
supervised QLoRA fine-tuning of Qwen3.8-27B. Ordered and shuffled conditions
were run sequentially on one H200.

## Data and comparison

Use the existing CSVs in `data/processed/mimic_training`, without rebuilding
the cohort or changing its split. Train on all 8,887 training patients (688
positives); validation and test each contain 2,963 patients (229 positives).
The split seed is 42. Both conditions start from fresh pretrained weights and
use training seed 42 and the same hyperparameters.

The preflight audit checks schemas, binary labels, row alignment, exact
sequence duplicates, and equality of each patient's code multiset and label
between ordered and shuffled versions. The existing visit-level files also
permit checking that all 14,813 patient identifiers are unique across splits.
Only aggregate counts and input hashes are recorded in the audit report;
patient identifiers are not copied into reports or prediction exports.

This experiment reuses the prepared diagnosis-code endpoint. The original
cohort-construction CSV is absent, so this is not an independent audit of the
clinical endpoint against the raw MIMIC tables. Within-admission ordering is
diagnosis sequence order, not necessarily clinical event time.

## Model and training

- Model: `Qwen/Qwen3.8-27B`, pinned revision
  `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`.
- Load the same audited text backbone used by the KIP Qwen experiment, with
  NF4 double quantization and BF16 computation. Vision and language-model
  output heads are excluded from the classification forward pass.
- Train LoRA adapters (rank 8, alpha 16, dropout 0.1) on the attention and
  hybrid-layer projections, plus a linear two-class head on the final
  unmasked token. Trainable parameters are FP32.
- Prompt: `Sequential events: <space-separated CCS codes>\nOutcome (0 or 1):`.
- Preserve complete sequences with dynamic right padding. Tokenization must
  reject sequences exceeding the 16,384-token limit; it never silently
  truncates. This preserves code content in the ordered/shuffled comparison.
  The actual tokenizer audit passed: maximum lengths are 8,386 tokens in
  training, 5,367 in validation, and 10,985 in test. Both conditions have
  identical per-split length summaries. Mean lengths are 377–387 tokens.
- Unweighted binary outcome cross-entropy; AdamW, learning rate `2e-5`, weight
  decay `0.01`, 6% warmup followed by linear decay. The schedule counts
  optimizer updates, including the final partial accumulation group.
- Initial microbatch 2, accumulation 16, effective batch 32; evaluation batch
  2. A verified CUDA out-of-memory error permits a fresh attempt with
  microbatch 1, accumulation 32, and evaluation batch 1.
- At most 30 epochs. Select the lowest validation cross-entropy; stop after
  five epochs without improvement, subject to a minimum of five epochs.
  No test result influences training, checkpoint selection, or stopping.

This is a new Qwen classification experiment, not an exact reproduction of
the old `train_mimic.py` LLM objective. That implementation combines prompt
language-model loss with classification loss, uses a nonlinear head, allows
truncation at 2,048 tokens, and defaults to patience 3 and effective batch 8.
Those differences must accompany comparisons with historical results.

## Evaluation and artifacts

After validation selects the checkpoint, evaluate the full test split once.
Report AUROC, average precision (the reported AUPRC convention), accuracy,
precision, recall, and F1. Report both threshold 0.5 and the threshold selected
for F1 on validation, using the existing 0.10–0.89 grid. Test prevalence is
approximately 7.7%, which provides context for average precision.

The initial run uses one training seed. Differences between ordered and
shuffled runs are exploratory until checked across additional seeds.

Artifacts are written under
`results/qwen38_27b_ckd_20260921_seed42/`: immutable launch/source/data
provenance, aggregate data audit, per-attempt manifests, training history,
status, selected adapter/head checkpoint, row-indexed predictions, and
metrics. Full base weights are never exported to the nearly full disk.

## Reproduction

See the release reproduction instructions for standalone commands. Download
the pinned model into a writable local cache and generate clinical inputs only
under credentialed MIMIC access. Patient-level outputs and weights from clinical
fits are excluded from this package.
